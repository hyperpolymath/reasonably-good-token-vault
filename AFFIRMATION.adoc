== What this is, and how it works

reasonably-good-token-vault (RGTV) is an alpha credential broker for AI
agents. It is three separate Rust crates, with no cargo workspace and one
`Cargo.lock` each. `vault-broker` is an axum HTTP server. It loads credential
values from `RGTV_CRED_<HINT>` environment variables, issues single-use,
time-limited grants, and hands a value back once per grant. `vault-worker` is
the same idea as a Cloudflare Worker, built with workers-rs for
`wasm32-unknown-unknown`. It keeps grants in a Durable Object and values in KV.
`rgtv-cli` is a client that redeems a grant and runs a command with the value
in its environment. The README already says the code is not post-quantum, not
formally verified, and not a password manager. This file checks that, and
everything else it says, against runs made at one commit.

=== The honest nuance you must not lose

* *"Tests pass" means zero tests.* `just test` exits 0 with `running 0 tests`
  for vault-broker and rgtv. `cargo test` on the worker (native target, not
  part of `just test`) also exits 0 with 0 unit tests and 0 doctests. A green
  `just test` is no evidence of behaviour.
* *Green lint is not a working server.* The broker passes `-D warnings` and
  still aborts at startup. Clippy does not run the router.
* *No post-quantum cryptography, and no claim of it.* A search of all three
  lockfiles for `kyber`, `dilithium`, `ml-kem`, `mlkem`, `ml-dsa`, `pqcrypto`,
  `oqs` and `aws-lc` found nothing. The CLI's TLS is rustls on ring.
  Which key-exchange groups it negotiates was not tested.
* *The broker speaks plain HTTP on all interfaces.* Source reading: it binds
  `[::]:9100` (`main.rs` l.25, 392, 418) with no TLS. The bearer token and
  every redeemed value cross that socket unencrypted unless something in front
  of it adds TLS.
* *Credentials are stored as plaintext.* Source reading: the broker comment
  "hint → encrypted value" (`main.rs` l.72) describes values read verbatim
  from environment variables. `vault-worker/wrangler.toml` l.41 says "hint →
  plaintext credential value", and l.43 records encryption as not yet done.
* *The bearer check is not constant-time.* Source reading: `auth != expected`
  at `vault-broker/src/main.rs` l.164 and `vault-worker/src/lib.rs` l.186. It
  is an ordinary string comparison.
* *The cargo-audit result is bounded by its database.* The run used the advisory

== Reproduce it yourself

On this machine `mise.toml` is untrusted and its shims shadow cargo. Do *not*
run `mise trust`: it would activate the banned toolchains declared there.
Strip mise from `PATH` instead. Run `must-check` before building, or keep the
target directory outside the tree, because `target/` changes its result.

[source,bash]
----
git clone https://github.com/hyperpolymath/reasonably-good-token-vault.git
cd reasonably-good-token-vault
git checkout 6baae4fbed7d310c0ea998485b5f6460839ac314
export PATH="$(echo "$PATH" | tr ':' '\n' | grep -v mise | paste -sd:)"
export CARGO_TARGET_DIR="$PWD/target"   # one target dir for all three crates

just must-check        # expect rc=0, "All must checks passed"
just trust-verify      # expect rc=0, "All trust verifications passed"
just aspect            # observed rc=141 (SIGPIPE under pipefail)

just build             # expect rc=0, broker and rgtv release builds
just check             # expect rc=0 (broker and CLI only)
just test              # expect rc=0, "running 0 tests" twice

cargo build --locked --release --target wasm32-unknown-unknown \
  --manifest-path vault-worker/Cargo.toml          # expect rc=0
cargo clippy --locked --target wasm32-unknown-unknown \
  --manifest-path vault-worker/Cargo.toml -- -D warnings   # expect rc=101
cargo test --locked --manifest-path vault-worker/Cargo.toml  # 0 tests

for c in vault-broker rgtv-cli vault-worker; do
  cargo audit --file "$c/Cargo.lock"; echo "rc=$?"
done   # expect 0, 1 (RUSTSEC-2026-0285), 0

RGTV_AGENT_TOKEN=planted-test-token \
RGTV_CRED_DUMMY_HINT=dummy-value-not-a-secret RGTV_PORT=39117 \
  timeout 10 ./target/release/vault-broker; echo "rc=$?"
# expect rc=134: panicked at src/main.rs:410:10,
# "Path segments must not start with `:`"

grep -inE 'kyber|dilithium|ml-kem|mlkem|ml-dsa|pqcrypto|oqs|aws-lc' \
  */Cargo.lock; echo "rc=$?"    # expect rc=1, no matches
